# Grand Mobile Support Copilot

Локальный прототип для сортировки жалоб и вопросов Grand Mobile. Он определяет категорию и приоритет, подбирает проверяемые пункты правил, составляет черновик и показывает результат администратору. Ответы игрокам и санкции автоматически не отправляются.

**Статус:** работающая техническая основа. Без ручной разметки используется эвристическая классификация; обученной на реальных метках модели пока нет. Конкурсные accuracy, macro-F1, качество черновиков на ru/kk/uz и отсутствие галлюцинаций ещё не подтверждены экспертной оценкой. [Карта проекта](PROJECT_MAP.md) показывает файлы и текущие ограничения; [полный план](docs/implementation-plan.md) содержит оставшиеся этапы.

## Запуск на Windows

Из корня репозитория:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe -m pip install --no-deps -e .
$env:GRAND_RULES_PATH = 'C:\path\outside\repo\rules.json'
.\scripts\run.ps1 -Action serve -Python .\.venv\Scripts\python.exe
```

Откройте `http://127.0.0.1:8000/`. Интерфейс позволяет разобрать обращение, просмотреть приоритет, утверждения, цитаты и причины, сохранить правку в браузере и отметить обращение для старшего. Копирование кнопкой доступно после проверки черновика. Порядок работы и ограничения хранения — в [инструкции интерфейса](docs/ui.md). `GET /health` проверяет наличие правил; схема API — `/docs`.

Пакетная обработка:

```powershell
.\scripts\run.ps1 -Action predict -InputPath C:\path\tickets.jsonl -OutputPath C:\path\predictions.jsonl -Python .\.venv\Scripts\python.exe
```

Внешний JSON содержит строковые номера пунктов в `draft_reply.cited`; полный раздел, хеш и текст можно получить через `POST /triage?format=internal` или `python -m app.batch --format internal`. Один входной JSONL → одна выходная строка, включая ошибки формата. [Контракт API](docs/api-contract.md). Для GNU Make доступна команда `make predict IN=... OUT=... RULES=...`; GNU Make на этом Windows-компьютере не проверялся. Сборка wheel и развёрнутая инструкция — в [E3](docs/submission.md).

Правила, обращения, метки, предсказания, модели и SQLite-файлы храните **вне Git**. Путь к правилам задаётся через `GRAND_RULES_PATH` или `--rules`. Обученную модель можно подключить через `GRAND_MODEL_PATH` или batch `--model`; без неё работает эвристика. Неверная настроенная модель останавливает запуск.

## Что реализовано

| Часть | Текущее поведение | Подробности |
|---|---|---|
| Категории и приоритет | Эвристический режим; подготовлены обучение TF-IDF, групповая проверка и калибровка после появления gold | [Обучение](docs/training.md) |
| Разметка | Слепая выборка, разделение по заявителям, проверка меток и конфликтов | [Руководство](docs/annotation-guide.md) |
| Язык | Консервативная эвристика ru/kk/uz; optional локальный fastText ещё не проверен на реальных обращениях | [Язык](docs/language.md) |
| Факты и правила | Роли и исходные поля утверждений; лексический поиск правил, составной ключ цитаты и отказ при неоднозначности | [Факты](docs/facts.md), [правила](docs/retrieval.md) |
| Черновик | Шаблоны ru/kk/uz/en; проверка структуры, цитат и соответствия шаблону, безопасный fallback | [Черновики](docs/drafts.md), [проверка](docs/safety.md) |
| История | Опциональные точные повторы и 5 обращений одного игрока за 60 минут | [История](docs/history.md) |
| Интерфейс | Локальная очередь по приоритету и редактор; нет интеграции с игрой | [Интерфейс](docs/ui.md) |

## Проверка и границы результата

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m pip check
```

Последняя проверка изменений интерфейса: 111 тестов прошли; wheel содержал HTML/CSS/JS. Чистая установка, API smoke и два batch-прогона по 1 000 строк выполнялись на том же компьютере. [Замер E2](docs/performance.md) дал локальный p95 до 0,54 мс для эвристик и шаблонов, без HTTP/очереди и без будущей обученной модели. Внешних inference-вызовов в этом режиме нет.

Для реальной оценки нужны заполненные метки B1 и независимый holdout. [Приватный пакет из 100 слепых пар](docs/eval-rubric.md) подготовлен, оценки администраторов и носителей kk/uz пока отсутствуют. Семантические дубли, экспертная релевантность правил, оценка готовых черновиков и финальный HTTP-бенчмарк ещё не завершены. Браузерные сценарии интерфейса необходимо проверить вручную.
