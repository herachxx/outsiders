# Grand Mobile Support Copilot

Помощник поддержки для Grand Mobile (Decentrathon 6.0, кейс 03). Он разбирает жалобу или внутриигровой репорт: определяет категорию, приоритет и язык, достаёт нужный пункт правил, пишет черновик ответа и решает, нужен ли человек. Ничего игрокам не отправляется автоматически, решения о наказании принимает администратор.

Работает на обычном процессоре, без внешних API и без GPU: **$0 за обращение, около 2 мс на разбор**.

## Чем проект силён

| Что | Как это сделано | Чем подтверждено |
|---|---|---|
| **Ни одной выдуманной цитаты** | Пункт правил определяется ключом (раздел, номер, хэш правил), проверяется на релевантность категории, а готовый черновик сверяется с шаблоном: любой лишний текст или чужой пункт блокируется | на 1000 обращениях valid 544 ответа с цитатами, все существуют в `rules.json`, защита не срабатывала; независимый валидатор |
| **Осторожные черновики** | Не обещают разбан, возврат средств или наказание другого игрока. Платежи, апелляции, подозрение на взлом и жалобы на игроков идут человеку, как в примере из ТЗ | тесты на запрещённые обещания, `needs_human` для всех чувствительных тем |
| **Скорость и цена** | Правила и шаблоны вместо тяжёлой модели | p95 около 2 мс (в процессе), 1000 обращений за 0,27 с на сам разбор, 33 МБ памяти, $0 |
| **Русский, казахский, узбекский, английский** | Свой определитель языка (казахские буквы, узбекская латиница, кириллица узбекского), замены cp1251 для казахских букв, шаблоны ответов на четырёх языках | тесты на смешанные и «сломанные» тексты; казахские тексты проверяет носитель языка |
| **Честные метрики** | Все цифры ниже с указанием, как они получены и чем ограничены | раздел «Метрики и их границы» |
| **Все три бонуса из ТЗ** | Дедупликация (1 игрок, 1 проблема, 5 обращений за час, близкие копии по хэшам слов), предложение шаблонов по кластерам из реальных ответов админов, интерфейс оператора с очередью, правкой и проверкой | тесты, скрипты `propose_templates.py`, `export_edits.py` |
| **Интерфейсы в стиле игры** | Портал игрока и панель оператора, вход с PBKDF2, защита CSRF и CSP, запуск двойным кликом | тесты интерфейса и входа |
| **Устойчивость** | Любая странная запись (пустой текст, длинный текст, лишние поля, мусорные типы) даёт безопасный результат, а не падение | прогон 1500 искажённых записей без сбоев |
| **Данные не в репозитории** | Правила, обращения, метки и модели лежат вне Git, как требует кейс; есть удаление данных по сроку | `.gitignore`, `scripts/purge_support.py` |

## Быстрый старт

Нужен Python 3.12 или новее.

**Windows:** двойной клик по `START_WINDOWS.bat`, затем откройте `http://127.0.0.1:8000/` (портал игрока) и `/admin` (панель оператора). Первый запуск предложит задать пароль оператора. **Linux и macOS:** `bash START_LINUX.sh`.

**Пакетная обработка (то, что запускает жюри):**

```bash
make predict IN=tickets.jsonl OUT=pred.jsonl
# или напрямую
python -m app.batch --input tickets.jsonl --output pred.jsonl --rules rules.json
```

Вход может быть JSONL (в том числе `.gz`) или JSON-массивом, выход повторяет форму входа. Путь к правилам берётся из `--rules`, затем из `GRAND_RULES_PATH`, затем ищется `rules.json` рядом. Без правил прогон не падает, ответы просто идут без цитат.

**HTTP-сервис:**

```bash
GRAND_RULES_PATH=rules.json python -m uvicorn app.api:app --host 127.0.0.1 --port 8000
```

Основной вызов `POST /triage`; для интеграции с Grand Mobile есть `POST /integration/ticket` (принимает запись так, как её выгружает игра, ключ `GRAND_API_KEY`).

**Проверка:**

```bash
python -m pytest -q                                   # 291 тест
python -m scripts.validate_predictions --input tickets.jsonl --predictions pred.jsonl --rules rules.json --taxonomy taxonomy.json
```

## Формат ответа

Точно как в ТЗ: `lang`, `category`, `priority`, `is_spam_or_duplicate`, `extracted {nickname, rule_refs, has_evidence, server}`, `draft_reply {lang, text, cited}`, `needs_human`, `confidence`, `reasons`. Ник, сервер и пункты правил берутся и из полей обращения, и из текста («Arman_Petrov», «на 12-м сервере», «2.1 ОП»). Пример черновика для оскорбления: приветствие, уточняющий вопрос, «Возможное нарушение: пункт 2.1 правил: «Запрещено прямое оскорбление…». Меру определяет администратор после проверки», подпись.

## Как это работает

```
обращение -> очистка и язык -> категория -> приоритет и эскалация -> пункт правил -> черновик -> проверка безопасности -> ответ
```

1. **Очистка.** Берётся только текст игрока до первого ответа админа. Нормализация, замена look-alike символов cp1251, ники и коды правил не мешают определению языка.
2. **Категория (14 кодов из taxonomy).** Правила по словам и сленгу игроков, пункт из поля «пункт правил» как подсказка, при нескольких темах побеждает названная первой; обращения без содержания считаются невалидными. Необязательная обученная модель добавляется там, где правила молчат.
3. **Приоритет и человек.** p0 для платежей и доступа к аккаунту, p1 для читов, обмана и рекламы, p2 для остального, p3 для вопросов и оффтопа. Вложение приоритет не меняет, потому что оно есть у каждой жалобы.
4. **Цитаты.** Пункт игрока (если релевантен) или пункт категории из taxonomy: оскорбления 2.1, читы 5.2, обман 4.1 и 4.2, жалобы на админов 1.3.1 и 3.4, DM по ситуации (5.3, 5.4, зелёная зона 32/1.1), пустые жалобы по «Правилам жалоб».
5. **Черновик.** Шаблон по типу обращения с вопросами, которых не хватает для разбора (где и когда, какое преимущество, как начался конфликт), просьбой о видео, если вложений нет.
6. **Проверка безопасности.** Цитаты по ключу, соответствие шаблону, отсутствие обещаний. Не прошло: нейтральный запасной текст и человек.

## Метрики и их границы

| Показатель | Значение | Как получено |
|---|---|---|
| Accuracy категории | 0,81 | 197 обращений holdout из пакета на 800 |
| Macro-F1 категории | 0,70 | там же |
| Accuracy приоритета | 0,90 | там же |
| Macro-F1 приоритета | 0,87 | там же |
| Калибровка confidence (ECE) | 0,05 | там же |
| Accuracy по пункту нарушения в ответе админа | 0,93 | 2453 жалобы отложенных заявителей, независимая проверка |
| Валидность ответа по контракту | 1000 из 1000 | валидатор на valid |
| Задержка, p95 | около 2 мс | замер в процессе |
| Стоимость | $0 | внешних вызовов нет |

**Важно.** В кейсе нет размеченных категорий и приоритетов. Метки для 800 обращений поставили мы сами с помощью ИИ-ассистента, независимой экспертной проверки пока нет, поэтому первые пять строк таблицы ориентировочные. Для проверки подготовлена выборка из 50 обращений для людей. Накладываются и другие границы: качество черновиков на слепой оценке администраторов и носителей казахского и узбекского мы не измеряли, а правило приоритета для «жалоб с доказательствами» в taxonomy допускает два прочтения (мы выбрали приоритет по категории, подробности в `docs/criteria.md`).

## Источники и лицензии

* **Данные кейса** (обращения, `rules.json`, `taxonomy.json`) выданы организаторами только для решения кейса, в репозитории их нет, удаление по сроку из условий.
* **Готовых моделей, внешних LLM-API и сторонних датасетов не используется.** Классификация, язык и черновики построены на правилах и шаблонах. Необязательная модель (scikit-learn) обучается локально на данных кейса и в репозиторий не входит.
* **Библиотеки:** FastAPI, Pydantic (MIT), Uvicorn, httpx, scikit-learn, joblib (BSD-3), Pillow (HPND), python-multipart (Apache-2.0), pytest (MIT). Определитель языка fastText подключается по желанию (код MIT, модели lid.176 под CC BY-SA 3.0), по умолчанию не используется.
* **Инструменты разработки:** код, тесты, документация и разметка делались командой с помощью ИИ-ассистента Claude (Anthropic).

## Ограничения и планы

* Казахские и узбекские тексты ответов проверяет носитель языка; узбекский пока не проверен.
* Семантические дубли находятся только при близком совпадении слов; точность на размеченных парах не измерена.
* Обученная модель даёт небольшой прирост, но не публикуется: условия кейса запрещают данные и производные выборки в репозитории.
* Интеграции с игрой нет: сервис принимает обращения и отдаёт разбор, отправку выполняет человек.
