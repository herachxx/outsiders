# Grand Mobile Support Copilot

Для продолжения разработки: [карта проекта](PROJECT_MAP.md) — дерево файлов, связи модулей, текущий этап и команды проверок.

Рабочая основа сервиса сортировки обращений для кейса Decentrathon 6.0. Текущая версия — **безопасный эвристический baseline**, а не готовое решение конкурса: категории и приоритеты в выданных данных не размечены, модель пока не обучена, тексты ответов шаблонные. Сервис не отправляет ответы и не назначает наказания.

## Быстрый старт (PowerShell)

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e '.[dev]'
$env:GRAND_RULES_PATH = 'C:\path\outside\repo\rules.json'
.\.venv\Scripts\python.exe -m uvicorn app.api:app --host 127.0.0.1 --port 8000
```

`POST http://127.0.0.1:8000/triage` принимает JSON обращения. `GET /health` показывает, загружены ли правила. Открытая схема API: `http://127.0.0.1:8000/docs`.

По умолчанию API и batch выдают строковые номера в `draft_reply.cited` по примеру PDF. Для полного состава цитат используйте `?format=internal` или CLI `--format internal`. Подробности и ошибки: [контракт A2](docs/api-contract.md).

Пакетный режим:

```powershell
.\.venv\Scripts\python.exe -m app.batch --input C:\path\tickets_valid.jsonl --output C:\path\pred.jsonl --rules C:\path\rules.json
```

На каждую строку входа записывается одна строка результата. Некорректный JSON даёт `{"error":"invalid_input"}` на той же позиции. Файлы с данными и предсказаниями держите **за пределами репозитория**. Скрипт не меняет исходный набор.

## Реализовано

- общий pipeline для HTTP и JSONL;
- валидация входа и отказ от использования исторического ответа администратора как признака;
- первичная категоризация и приоритет по явным правилам;
- обязательная передача жалоб, платежей и вопросов об аккаунте человеку;
- составной ключ цитаты `(section_id, ref, rules_hash)` и отказ от неоднозначных пунктов;
- выбор раздела общих правил для нескольких однозначно распознанных категорий жалоб;
- нейтральные черновики без обещаний наказания или возмещения;
- ответ 503 при попытке работать без загруженных правил;
- тесты базовых сценариев.

Пробный прогон по 1 000 строкам `tickets_valid.jsonl` дал 0 ошибок формата, 582 обращения категории `complaint.other`, 996 маршрутов `needs_human=true` и 18 черновиков с цитатой. Это **диагностика покрытия**, не оценка accuracy: меток категории и приоритета в файле нет. Такой baseline требует ручной разметки и обучения до конкурсной сдачи.

## Следующие задачи

Инструменты B1 готовы: `python -m scripts.sample_for_labeling` и `python -m scripts.merge_labels`. Они создают файлы только вне репозитория. Подробная инструкция — в разделе B1 [руководства разметчика](docs/annotation-guide.md). Ручные метки и обученный на реальных данных классификатор ещё не готовы.

Инструменты B2 готовы: `python -m scripts.train` обучает отдельные TF-IDF модели complaint/report, сравнивает их с эвристиками на проверке по группам заявителей внутри train и сохраняет артефакты вне Git. Holdout не используется. Установка `.[dev,ml]`, подготовка gold и подключение через `GRAND_MODEL_PATH` или batch `--model` описаны в [инструкции обучения](docs/training.md). Без модели сервис использует эвристики; confidence пока не откалиброван.

Черновая политика маршрутизации вынесена в `app/priority.py`; границы категорий и спорные решения описаны в [инструкции разметчика](docs/annotation-guide.md). В ответах присутствует `policy_draft` до утверждения владельцем кейса. JSON Schema в `configs/` проверяет структуру внешней taxonomy; уникальность кодов и соответствие актуальному контракту проверяются дополнительно.

1. Утвердить черновую taxonomy и протокол ручной разметки.
2. Разметить категории и приоритеты; создать независимый holdout по заявителям.
3. Обучить и оценить классификатор; откалибровать уверенность по языкам.
4. Реализовать поиск дублей по истории и бонусный сценарий «5 тикетов по одной проблеме от игрока за час»; оценить ложные совпадения.
5. Улучшить подбор точного раздела правил, оценить релевантность цитат.
6. Проверить черновики администраторами и носителями казахского/узбекского.
7. Измерить p95 и стоимость на целевом оборудовании, затем добавить интерфейс администратора.

Полный [план](docs/implementation-plan.md) хранится в проекте. Сырые обращения, производные выборки, хеши игроков и содержимое правил нельзя публиковать в репозитории.
