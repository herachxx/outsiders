# Grand Mobile Support Copilot

Помощник поддержки для Grand Mobile (Decentrathon 6.0, кейс 03). Он разбирает жалобу из лаунчера или короткий репорт из игры: определяет язык, категорию и приоритет, находит нужный пункт правил, готовит черновик ответа на языке игрока и честно говорит, когда нужен человек.

Проект реализован на Python 3.12+, FastAPI и Pydantic. По умолчанию используются правила и шаблоны; локальный классификатор scikit-learn подключается отдельно. Сервис работает на CPU. В режиме по умолчанию внешних inference-вызовов нет.

## Возможности и критерии оценки

| Критерий | Вес | Реализация | Что ещё требуется подтвердить |
|---|---:|---|---|
| Классификация | 25% | Категории и приоритеты, эвристики и необязательная обученная модель | Accuracy категории и macro-F1 приоритета на независимой разметке и скрытом тесте |
| Качество черновиков | 30% | Шаблоны по типу обращения, уточняющие вопросы, редактор оператора | Слепая оценка 100 черновиков администраторами по шкале 1–5 |
| Достоверность цитат | 20% | Проверка раздела, номера, хеша правил и релевантности; безопасный fallback | Проверка применимости цитат экспертами; отсутствие ошибок в локальном прогоне не гарантирует их отсутствие на любом входе |
| Казахский и узбекский | 15% | Определение языка, обработка отдельных искажений кодировки, шаблоны kk/uz | Оценка носителями на репрезентативной выборке |
| Стоимость и задержка | 10% | Локальная обработка, скрипты замера pipeline, HTTP и полного процесса | Повторный замер финальной конфигурации: p95 ≤ 5 с, внешняя стоимость ≤ $0,002 или локальная модель |

Дополнительно реализованы портал игрока, очередь оператора, вложения, поиск, редактирование, проверка черновика, локальные статусы и журнал действий. Кнопка «Отправить» завершает локальный рабочий сценарий; доставки ответа в реальную игру нет. Дедупликация использует точное и близкое совпадение слов в часовом окне. Скрипт кластеризации предлагает шаблоны для утверждения человеком.

## Стек и зависимости

Источник зависимостей — `pyproject.toml`. Для локальной установки интерфейса и инструментов проверки:

```powershell
python -m pip install -e ".[ui,dev]"
```

Для обучения добавьте extra `ml`, для необязательного fastText — `language`. Windows-установщик читает зависимости из `pyproject.toml`; `httpx` входит в основной набор. Полный список переданных отдельно библиотек не требуется устанавливать: CatBoost, Streamlit, pybind11, rapidfuzz и orjson не входят в текущий основной стек. C++-ядро, SIMD-батчинг и Qwen в `main` не реализованы.

## Быстрый старт

Нужен Python 3.12 или новее.

**Интерфейсы.** Windows: двойной клик по `START_WINDOWS.bat`. Linux и macOS: `bash START_LINUX.sh`. Откройте `http://127.0.0.1:8000/` (портал игрока) и `/admin` (панель оператора, первый запуск предложит задать пароль).

**Пакетная обработка (то, что запускает жюри).**

```bash
make predict IN=tickets.jsonl OUT=pred.jsonl
# или напрямую
python -m app.batch --input tickets.jsonl --output pred.jsonl --rules rules.json
```

Путь к правилам берётся из `--rules`, затем из `GRAND_RULES_PATH`, затем ищется `rules.json` рядом. Без правил прогон не падает, ответы просто идут без цитат. Форму выхода можно задать флагом `--output-format json|jsonl`.

**HTTP-сервис.**

```bash
GRAND_RULES_PATH=rules.json python -m uvicorn app.api:app --host 127.0.0.1 --port 8000
```

`POST /triage` разбирает обращение. Для интеграции с Grand Mobile есть `POST /integration/ticket`: он принимает запись в том виде, как её выгружает игра, и проверяет ключ, если задан `GRAND_API_KEY`. Без переменной проверка ключа отключена; стандартный запуск привязан к localhost.

**Проверка.**

```bash
python -m pytest -q
python -m scripts.validate_predictions --input tickets.jsonl --predictions pred.jsonl --rules rules.json --taxonomy taxonomy.json
```

## Пример

Иллюстрация формата запроса из ТЗ (не результат экспертной оценки):

```json
{ "kind": "complaint", "messages": [ { "role": "player", "attachments": 2,
  "text": "Arman_Petrov оскорблял меня и мою семью в чате, скрины есть, 2.1 ОП" } ] }
```

Иллюстрация ответа в формате сдачи. Текст сокращён, значение confidence зависит от подключённой таблицы и модели. Для воспроизводимой проверки используйте batch-команду и валидатор ниже:

```json
{ "lang": "ru", "category": "complaint.insult", "priority": "p2", "is_spam_or_duplicate": false,
  "extracted": { "nickname": "Arman_Petrov", "rule_refs": ["2.1"], "has_evidence": true, "server": null },
  "draft_reply": { "lang": "ru", "cited": ["2.1"], "text": "Здравствуйте! Благодарим за обращение. Укажите, где произошло оскорбление (общий, рабочий или голосовой чат) и когда. Обстоятельства и возможное нарушение должен проверить администратор. Приложенные материалы рассмотрит администратор. Возможное нарушение: пункт 2.1 правил: «Запрещено прямое, завуалированное и провокационное оскорбление личности игрока…». Меру ответственности определяет администратор после проверки. С уважением, администрация Grand Mobile." },
  "needs_human": true, "confidence": 0.964,
  "reasons": ["решение о наказании подтверждает администратор", "confidence_empirical", "evidence_not_verified"] }
```

Ответ на казахском для жалобы на читы («Серверде читер бар, ақшамды ұрлап кетті…»): приветствие, вопрос о том, какое преимущество использует игрок и когда, фраза «Мүмкін бұзушылық: ережелердің 5.2 тармағы. Жауапкершілік шарасын әкімші тексеруден кейін анықтайды» и подпись. Русская цитата правила в казахский и узбекский текст не подмешивается.

## Как это работает

```
обращение
  -> очистка (только текст игрока до ответа админа) и определение языка
  -> категория (правила, сленг, подсказка из поля «пункт правил», при нескольких темах первая названная)
  -> приоритет и эскалация (платёж, аккаунт, апелляция, жалоба на игрока: человек)
  -> пункт правил по ключу (раздел, номер, хэш) и проверка релевантности
  -> черновик из шаблона под тип обращения
  -> проверка безопасности (цитаты, соответствие шаблону, отсутствие обещаний)
  -> ответ по контракту
```

* **Категория** определяется по смыслу сообщения: «оск родни», «дб в зз», «не согласен с наказанием», «кинули на авторынке», русские и узбекские слова. Обращения без содержания (одни ссылки или цифры) помечаются невалидными.
* **Приоритет:** p0 платежи и доступ к аккаунту, p1 читы, обман и реклама, p2 остальные жалобы, p3 вопросы и оффтоп. Вложение приоритет не меняет: оно есть у каждой жалобы.
* **Цитаты:** пункт, названный игроком (если он подходит по смыслу), иначе пункт категории из `taxonomy.json` (оскорбления 2.1, читы 5.2, обман 4.1 и 4.2, жалобы на админов 1.3.1 и 3.4, DM по ситуации, пустые жалобы по «Правилам жалоб»).
* **Черновик:** вопросы, которых не хватает для разбора (где и когда, какое преимущество, как начался конфликт), просьба о видеозаписи, если вложений нет, осторожная фраза о возможном нарушении. Если проверка не пройдена, вместо черновика отдаётся нейтральный текст и обращение уходит человеку.
* **Необязательная модель.** Если задан `GRAND_MODEL_PATH`, обученный классификатор помогает там, где правила не нашли тему. Обучается локально и в репозиторий не входит (условия кейса запрещают публиковать производные данных).

## Локальный отчёт

Следующие показатели перенесены из отчёта команды. При редактировании документации этот прогон повторно не запускался; значения относятся к конкретной версии и конфигурации, а не к скрытому тесту.

Данные валидации: 1000 обращений (817 жалоб, 183 репорта), без меток категории и приоритета.

| Показатель | Значение |
|---|---|
| Валидность ответа по контракту | 1000 из 1000, ошибочных строк нет |
| Ответов с подтверждённой цитатой | 544 из 1000, выдуманных пунктов 0 |
| Доля «нужен человек» | 92,7% всего: жалобы 100% (817 из 817, как в примере ТЗ), репорты 60% (110 из 183) |
| Приоритеты | p0 2, p1 62, p2 803, p3 133 |
| Языки ответа | русский 685, узбекский 121, казахский 7, прочие и неопределённые 187 (короткие фрагменты вроде «+» и «помогите») |
| Внешние inference-расходы на обращение | $0 в режиме правил и шаблонов; оборудование, электричество и работа оператора не учтены |
| Задержка в процессе | p50 0,34 мс, p95 0,73 мс, p99 1,26 мс; 1000 обращений за 0,27 с на разбор, около 1,9 с вместе с запуском процесса; пик памяти 33 МБ |
| Задержка через HTTP | p95 около 80 мс при 20 параллельных запросах на одном компьютере |

Примеры черновиков приведены выше; в `docs/drafts.md` описаны шаблоны, в `docs/kk-review.md` казахские тексты для вычитки носителем.

## Предварительные метрики качества

Эти значения получены на метках, подготовленных с помощью ИИ. Они показывают согласие с этой разметкой и не заменяют независимую человеческую оценку.

| Показатель | Значение | Как получено |
|---|---|---|
| Accuracy категории | 0,81 | 197 обращений holdout из пакета на 800 |
| Macro-F1 категории | 0,70 | там же |
| Accuracy приоритета | 0,90 | там же |
| Macro-F1 приоритета | 0,87 | там же |
| Калибровка confidence (ECE) | 0,05 | там же |
| Совпадение с пунктом нарушения из ответа админа | 0,93 | 2453 жалобы отложенных заявителей; сравнение с историческим пунктом нарушения, не экспертная проверка категории |

**Важно.** В выданных данных нет размеченных категорий и приоритетов. Метки для 800 обращений поставили мы сами с помощью ИИ-ассистента, независимой экспертной проверки пока нет, поэтому первые пять строк таблицы ориентировочные. Для проверки людьми подготовлена выборка из 50 обращений. Не измерено: слепая оценка черновиков администраторами и носителями казахского и узбекского. Правило приоритета для «жалоб с доказательствами» в taxonomy допускает два прочтения; мы выбрали приоритет по категории (подробности в `docs/criteria.md`).

## Источники и лицензии

* **Данные кейса** (обращения, `rules.json`, `taxonomy.json`) выданы организаторами только для решения кейса. В репозитории их нет, данные удаляются в срок из условий (скрипт `scripts/purge_support.py`).
* **Готовых моделей, внешних LLM-API и сторонних датасетов не используется.** Язык, категория, приоритет и черновики построены на правилах и шаблонах. Необязательная модель (scikit-learn) обучается локально на данных кейса.
* **Библиотеки:** FastAPI, Pydantic (MIT), Uvicorn, httpx, scikit-learn, joblib (BSD-3), Pillow (HPND), python-multipart (Apache-2.0), pytest (MIT). Определитель языка fastText подключается по желанию (код MIT, модели lid.176 под CC BY-SA 3.0), по умолчанию не используется.
* **Инструменты разработки:** команда использовала Claude (Anthropic) и Codex (OpenAI) для кода, тестов и документации; происхождение разметки раскрыто в разделе метрик.

## Ограничения и планы

* Для подтверждения качества kk/uz нужны зафиксированные оценки носителей; полноценная независимая оценка пока не завершена.
* Семантические дубли находятся при близком совпадении слов; точность на размеченных парах не измерена.
* Обученная модель даёт небольшой прирост, но не публикуется. Режим правил самодостаточен и именно он запускается по умолчанию.
* Интеграции с игрой нет: сервис принимает обращения и отдаёт разбор, ответ отправляет человек.
* Планы: экспертная разметка и слепая оценка черновиков, расширение правил для узбекского, подключение утверждения шаблонов кластеров прямо в панели оператора.

## Проверка примеров перед сдачей

README описывает решение и условия измерений. Фактический результат определяется запуском кода на входных обращениях. Примеры в документации не заменяют скрытый тест и слепую оценку черновиков.

Для воспроизводимого сравнения сохраните версию кода, конфигурацию модели и правил, входной файл и результат batch-прогона. Затем запустите `scripts.validate_predictions`. Сравнение с историческим ответом администратора выполняйте отдельно: ответ администратора не передаётся классификатору как признак.

Полезные синтетические сценарии для демонстрации: оскорбление с вложениями; потеря доступа на kk; списание денег без доната на uz; несуществующий пункт 99.9. В каждом случае показывайте фактический JSON сервиса. Не обозначайте вручную написанный ответ как результат модели или реальный ответ администратора.
