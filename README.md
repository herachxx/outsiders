# Grand Mobile Support Copilot

Локальный прототип для сортировки жалоб и вопросов Grand Mobile. Он определяет категорию и приоритет, подбирает проверяемые пункты правил, составляет черновик и показывает результат администратору. Ответы игрокам и санкции автоматически не отправляются.

**Статус:** работающая техническая основа. По умолчанию работает режим правил (его запускают без модели); необязательная модель обучена на метках, поставленных Claude, а не людьми. Конкурсные accuracy, macro-F1, качество черновиков на ru/kk/uz и отсутствие галлюцинаций ещё не подтверждены экспертной оценкой. [Карта проекта](PROJECT_MAP.md) показывает файлы и текущие ограничения; [полный план](docs/implementation-plan.md) содержит оставшиеся этапы.

## Запуск на Windows

Из корня репозитория:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe -m pip install --no-deps -e .
$env:GRAND_RULES_PATH = 'C:\path\outside\repo\rules.json'
.\scripts\run.ps1 -Action serve -Python .\.venv\Scripts\python.exe
```

Откройте `http://127.0.0.1:8000/`. Интерфейс позволяет разобрать обращение, просмотреть приоритет, утверждения, цитаты и причины, сохранить правку в браузере и отметить обращение для старшего. Копирование кнопкой доступно после проверки черновика. Порядок работы и ограничения хранения — в [инструкции интерфейса](docs/ui.md). `GET /health` проверяет наличие правил; схема API — `/docs`.

Пакетная обработка:

```powershell
.\scripts\run.ps1 -Action predict -InputPath C:\path\tickets.jsonl -OutputPath C:\path\predictions.jsonl -Python .\.venv\Scripts\python.exe
```

Внешний JSON содержит строковые номера пунктов в `draft_reply.cited`; полный раздел, хеш и текст можно получить через `POST /triage?format=internal` или `python -m app.batch --format internal`. Один входной JSONL → одна выходная строка, включая ошибки формата. [Контракт API](docs/api-contract.md). Для GNU Make доступна команда `make predict IN=... OUT=... RULES=...`; GNU Make на этом Windows-компьютере не проверялся. Сборка wheel и развёрнутая инструкция — в [E3](docs/submission.md).

Правила, обращения, метки, предсказания, модели и SQLite-файлы храните **вне Git**. Путь к правилам задаётся через `GRAND_RULES_PATH` или `--rules`. Обученную модель можно подключить через `GRAND_MODEL_PATH` или batch `--model`; без неё работает эвристика. Неверная настроенная модель останавливает запуск.

## Что реализовано

| Часть | Текущее поведение | Подробности |
|---|---|---|
| Категории и приоритет | Эвристический режим; подготовлены обучение TF-IDF, групповая проверка и калибровка после появления gold | [Обучение](docs/training.md) |
| Разметка | Слепая выборка, разделение по заявителям, проверка меток и конфликтов | [Руководство](docs/annotation-guide.md) |
| Язык | Консервативная эвристика ru/kk/uz; optional локальный fastText ещё не проверен на реальных обращениях | [Язык](docs/language.md) |
| Факты и правила | Роли и исходные поля утверждений; лексический поиск правил, составной ключ цитаты и отказ при неоднозначности | [Факты](docs/facts.md), [правила](docs/retrieval.md) |
| Черновик | Шаблоны ru/kk/uz/en; проверка структуры, цитат и соответствия шаблону, безопасный fallback | [Черновики](docs/drafts.md), [проверка](docs/safety.md) |
| История | Опциональные точные повторы и 5 обращений одного игрока за 60 минут | [История](docs/history.md) |
| Интерфейс | Локальная очередь по приоритету и редактор; нет интеграции с игрой | [Интерфейс](docs/ui.md) |

## Проверка и границы результата

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m pip check
```

Последняя полная проверка: 224 теста прошли (`pytest -q`), `pip check` без ошибок. [Замер E2](docs/performance.md): локальный p95 до 0,54 мс для эвристик и шаблонов без модели; с обученной моделью 1 000 обращений обрабатываются за 0,94 с после загрузки (около 3,4 с на загрузку модели). Внешних inference-вызовов нет, стоимость токенов $0.

Предварительная оценка на 800 обращениях пакета B1: **разметку поставил Claude, а не человек**, поэтому цифры ориентировочные. На holdout accuracy категории 0,80 (режим правил), приоритета 0,89, macro-F1 приоритета 0,86. Выборка для проверки человеком — `private/human-review-claude-labels`. Разбор — в [карте проекта](PROJECT_MAP.md).

Таблица соответствия критериям жюри — [criteria.md](docs/criteria.md).

HTTP-вход для Grand Mobile (`POST /integration/ticket`) описан в [integration.md](docs/integration.md).

Для реальной оценки нужны заполненные метки B1 и независимый holdout. [Приватный пакет из 100 слепых пар](docs/eval-rubric.md) подготовлен, оценки администраторов и носителей kk/uz пока отсутствуют. Семантические дубли, экспертная релевантность правил, оценка готовых черновиков и бенчмарк финальной конфигурации ещё не завершены. Локальный HTTP-бенчмарк текущего baseline описан в [замерах E2](docs/performance.md). Браузерные сценарии интерфейса необходимо проверить вручную.

Пакет B1 можно размечать по одному обращению через `python -m scripts.label_cli --package ../private/annotation-b1 --annotator reviewer_1`; инструкция и правила категорий — в [руководстве по разметке](docs/annotation-guide.md). Инструмент сохраняет человеческие решения локально и не создаёт метки автоматически.

Для независимой второй оценки подготовлен отдельный приватный пакет на 160 задач с пустыми метками. Команды разметки и объединения приведены в том же руководстве.

Полный batch-прогон текущих эвристик и шаблонов на 1000 реальных valid-обращений занял 1,918 с с пиком RAM 33,25 МБ. Скрипт `scripts.benchmark_process` учитывает запуск отдельного процесса и запись ответов; команда и ограничения сравнения — в [замерах E2](docs/performance.md). Качество обученной модели этим прогоном не измерено.
