# Интерфейсы: портал игрока и рабочее место оператора

Слиты изменения интерфейса из ветки `combined` (UI/UX): остальная логика этой ветки не переносилась.

| Адрес | Что это | Подробнее |
|---|---|---|
| `/` | портал игрока: шесть категорий обращений, форма, статус по личному токену, правила и ссылки на официальный Help Center и Discord | [player-ui.md](player-ui.md) |
| `/admin` | панель оператора: очередь с фильтрами, обращение, проверка и правка черновика, статусы, вложения, журнал действий | [admin-ui-v2.md](admin-ui-v2.md), [operator-workflow.md](operator-workflow.md) |
| `/admin/setup`, `/admin/login` | первый запуск (пароль не короче 12 символов, только с этого компьютера) и вход | [operator-workflow.md](operator-workflow.md) |

Запуск: `GRAND_RULES_PATH=... GRAND_OPERATOR_CONFIG=<приватный файл вне репозитория> python -m uvicorn app.api:app`. Без правил портал открывается, но разбор отдаёт 503, а обращения получают безопасный ручной разбор. Загрузка скриншотов требует `pip install .[ui]` (Pillow и python-multipart); без них остальное работает, а загрузка отвечает понятной ошибкой.

Безопасность: вход оператора с PBKDF2, подписанные куки, CSRF-токен на изменяющих запросах, ограничение числа попыток, заголовки CSP, `nosniff`, запрет встраивания. Сообщения игроков показываются только как текст (`textContent`), `innerHTML` в интерфейсе не используется. База обращений и загруженные файлы лежат локально (`GRAND_DB_PATH`, `GRAND_UPLOAD_DIR`, по умолчанию `data/`, папка в `.gitignore`); `scripts/purge_support.py --days 14` удаляет старые данные по сроку из условий кейса. `scripts/seed_demo.py` создаёт пять синтетических обращений с условными правилами для показа интерфейса.

Правки оператора как обучающий сигнал (бонус из PDF): `python -m scripts.export_edits --output ../private/edits.jsonl` выгружает из базы исходный и итоговый черновик, категорию, приоритет, статус и признак проверки. Файл содержит тексты обращений: хранить вне Git.

Полоса обработки сервиса (`handling_auto|review|escalate` в `reasons`) и кластеры шаблонов — в [integration.md](integration.md) и ниже.

## Предложение шаблонов по кластерам (бонус)

`python -m scripts.propose_templates --train tickets_train.jsonl.gz --output ../private/templates-report-v1.json --kind report` кластеризует обращения (TF-IDF + MiniBatchKMeans) и для каждого кластера предлагает самые частые **реальные ответы администраторов** с заменой ников, номеров и ссылок на плейсхолдеры `{nick}`, `{n}`. Ничего не выдумывается: шаблон появляется, только если администраторы уже так отвечали. В отчёте есть размер кластера, ключевые слова, доминирующая категория и поле `approved: null`: шаблон нужно утвердить вручную. Отчёт приватный и хранится вне Git; полезнее запускать с `--kind complaint`, потому что на репортах самый частый ответ «Приветствую, слежу за вами».

## Запуск двойным кликом

`START_WINDOWS.bat` (Windows) и `START_LINUX.sh` (Linux/macOS) проверяют Python 3.12+, создают `.venv`, один раз ставят зависимости (нужен интернет, включая `Pillow` и `python-multipart` из extra `ui`; scikit-learn добавляется только если задан существующий `GRAND_MODEL_PATH`), открывают мастер первого запуска `/admin/setup` и запускают сервер на `127.0.0.1`. `python -m scripts.launch` делает то же из уже созданного окружения (`--reset` меняет пароль), `scripts/dev_start.py` поднимает тестовый экземпляр с одноразовым паролем и только для локальной проверки. Пароль оператора хранится в виде PBKDF2 в `data/operator.json` (права 0600 в Unix), открытого пароля нигде нет.

Кнопки из регламента (бонус «интерфейс админа»): **«Отправить»** проверяет черновик, переводит обращение в «Решено» и пишет это в журнал (в игру ничего не уходит, текст отправляют вручную); **«Сохранить»** сохраняет правку на сервере (правка попадает в базу и в выгрузку `export_edits`); **«Передать на проверку»** эскалирует обращение. Очередь с фильтрами и поиском, черновик и журнал действий находятся на той же странице.

## Панель оператора, версия 2

Панель перестроена: одна прокручиваемая страница обращения вместо вкладок. Сверху видно состояние помощника (чип «Помощник работает · правила и шаблоны», данные из `/api/status`), справа от очереди сразу идут: что написал игрок, что понял помощник (категория, приоритет, язык, уверенность, причины простым языком, найденные пункты правил, время разбора), редактор ответа и действия. Кнопка «Как работает помощник» показывает состояние и запускает самопроверку на четырёх тестовых обращениях (`POST /admin/api/selftest`, ничего не сохраняется). Из панели есть ссылка на страницу игрока, на странице игрока и в формах входа есть ссылки обратно. Горячие клавиши: `/` поиск, `J` и `K` следующее и предыдущее обращение. Поддержаны светлая и тёмная темы, мобильный режим с переходом «очередь → обращение».

Откат к прежнему виду: `git checkout ui-v1-before-redesign` (тег) или ветка `backup/ui-v1`.
