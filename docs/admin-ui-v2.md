# Grand Mobile — операторская админка, v2

## Принципы

Операторский экран, а не маркетинговый лендинг: минимум декоративных элементов, высокая плотность полезной информации, последовательный рабочий процесс. Нейтральная светлая палитра + тёмная узкая боковая панель + один акцентный жёлтый цвет. Статусные цвета применяются только к приоритетам. Используются векторные иконки в SVG; нет внешних CSS, шрифтов, сторонних библиотек и изображений.

Экран поделён на четыре зоны:
1. Навигация (узкая вертикальная панель).
2. Очередь (поиск, фильтры, приоритеты, выбор обращения).
3. Разбор (оригинал, факты, цитаты, основания решения, сервер и язык).
4. Решение (маршрутизация, редактируемый черновик, проверка, копирование, эскалация, локальное сохранение).

На узких экранах зоны идут последовательно сверху вниз, без горизонтального скролла. При ширине от 761 до 1140 px панель решения переходит под содержимое обращения.

## Настоящие возможности

- `/admin` — админка, `/` — клиентский интерфейс из предыдущей версии.
- Форма отправляет **реальный** `POST /triage?format=internal` в локальный FastAPI при загруженных правилах.
- «Проверить ответ» вызывает **реальный** `/draft/check`. При неудачной проверке копирование заблокировано.
- Фильтрация и поиск по локальной очереди, разметка для старшего, редактирование и сохранение текущей очереди в localStorage.
- Демо-данные: `http://localhost:8000/admin?demo=1` или кнопка «Показать демо-данные»; все синтетические и не попадают в localStorage при сохранении.
- Самодостаточный HTML-макет вне FastAPI: `grand_mobile_admin_final_preview.html` из пакета. Он содержит только синтетические данные и **не проверяет** черновики сервером.

## Ограничения и безопасность

- Нет аутентификации администраторов, серверной очереди, хранения обращений на сервере или реальной отправки в Grand Mobile. **Не публиковать `/admin` в интернет** без этих механизмов.
- Эскалация — локальный статус, не пересылка сотруднику. «Сохранить» — localStorage в одном браузере; на общем устройстве для чувствительных обращений не использовать.
- Файлы игрока не загружаются и не анализируются: виден только переданный `images_count`. Оператор не должен трактовать факт наличия файла как доказательство.
- Демо-цитаты — только синтетический пример оформления и **не подтверждают** существование пункта правил.
- Если правил нет, `/triage` и `/draft/check` вернут ошибку 503. На продакшн нужны реальные правила и актуальная модель.

## Проверки

- Python pytest: 191 тест пройден после обновления проверки заголовка админки.
- Playwright Chromium via set_content: desktop 1600px, laptop 1366px, mobile 390px. Консоль без JS ошибок, document.scrollWidth соответствует ширине экрана.
- В браузере проверены: фильтры, поиск, переключение тикетов, редактирование, эскалация, открытие и закрытие диалога.
- Прямая проверка реальных отправок на сервер через браузер в этом окружении невозможна из-за политики браузера, но API проверяется тестами проекта через TestClient.
