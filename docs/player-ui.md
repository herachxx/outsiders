# Grand Mobile × Outsiders · Player Support UI

Вложения учитываются только после успешного сохранения файла: выбранные в браузере файлы не подтверждают их наличие на сервере. Каждое сохранение обновляет счётчик, результат разбора и версию тикета, сбрасывает подтверждение черновика. Исходный шаблон обновляется; ручная правка оператора сохраняется и требует новой проверки. В resolved/closed добавление файлов запрещено до повторного открытия. При частичной ошибке загрузки учитываются только успешно сохранённые файлы, а игрок видит предупреждение. Без загруженных правил сохраняются прежняя категория и ручной маршрут.

## Цель и основные решения

Проект — адаптивный **игровой** слой над существующим FastAPI endpoint `POST /triage?format=internal`. Мы не подменяем официальный Help Center, не обещаем автоматическую модерацию и не создаём фиктивное серверное подтверждение. UI показывает **предварительный ответ**, а не решение администрации.

### Откуда взяты идеи

- В Grand Mobile встречаются тёмные игровые панели, яркий жёлтый цвет действий, ярко выраженные карточки и контрастная типографика. Иллюстрация города и спортивного автомобиля в hero — **оригинальный SVG, вдохновлённый игровой атмосферой**, не копия ассета Grand Mobile.
- В обновлённом лаунчере игроку показываются UID, сервера, персонажи, магазин и раздел жалоб; интерфейс поддержки должен быть таким же быстрым, наглядным и понятным.
- Официальный Help Center предлагает разделы про аккаунты, платежи, нарушения и санкции; это приоритетные ветки навигации.
- Официальный канал для предложений — Discord, раздел `#предложения`: `https://discord.gg/grnd`. Клиентский интерфейс показывает прямую ссылку после обработки предложения.

## UX-маршрут

1. `/`: пользователь выбирает одну из шести категорий: **игровой вопрос**, **жалоба**, **техническая проблема**, **покупки**, **аккаунт**, **предложение**.
2. Пишет свободный текст (до 20 000 символов); сервер и никнейм — необязательные поля, ник показывается только для жалобы.
3. Кнопка отправляет запрос к существующему `/triage?format=internal`, показывает реальную загрузку, затем ответ, подтверждённые правила и метку `Нужен специалист` или `Предварительный ответ`.
4. Тикет попадает в локальную историю вкладки; оператор в **том же браузерном профиле** может увидеть его на `/admin` после сохранения в локальную очередь. Это демонстрационный механизм, **не серверная очередь и не передача Grand Mobile**.
5. Кнопка нового вопроса очищает форму; ссылки ведут на настоящий Help Center и официальный Discord для идей. Ошибки API (в т. ч. 503 без правил) показываются явно.

### Состояния

- `service unavailable`: красноватый статус; запрос можно отправить, но будет понятное сообщение о необходимости базы правил.
- `loading`: кнопка блокируется, показывается текст «Обрабатываем…» и состояние запроса, без искусственной задержки.
- `success`: ответ отображается сразу после сетевого ответа, показывается **фактически измеренное** время клиента (HTTP + сеть + обработка); абсолютные миллисекунды не обещаются.
- `needs_human`: отдельный заметный блок объясняет, что это не решение администрации, и предлагает официальный путь обращения.
- `proposal`: отдельная карточка направляет к каналу `#предложения` в официальном Discord.
- `local history`: сохраняется на время жизни вкладки через sessionStorage; продакшен-хранение не заявляется.

Шрифты — системный stack без внешних загрузок. Layout: desktop sidebar, compact topbar, hero, 3×2 category grid, support form + help sidebar, response. На телефоне — hero, карточки 2×3 и нижняя навигация. Эффекты: hover, glow, city entrance, loading, плавное появление ответа; `prefers-reduced-motion` отключает движение. Поля имеют labels, навигация — focus states, динамический текст вставляется через `textContent` для защиты от HTML-инъекций.

## Публичный API и ограничения

Исходный запрос:

```json
{
  "kind": "complaint",
  "messages": [{"role": "player", "text": "Игрок нарушил правила..."}],
  "images_count": 0,
  "region": "01",
  "reported_nick": "Example_Name"
}
```

POST `/triage?format=internal` возвращает `lang, category, priority, needs_human, draft_reply, extracted, reasons`. UI не меняет модель и не придумывает `cited` — показывает только цитаты, возвращённые сервером. Жалобы всегда требуют человека, как указано в конкурсном ТЗ; это отдельно закреплено регрессионным тестом.

Отдельная категория `proposal` отсутствует в конкурсном контракте — UI отправляет её как `report` и рекомендует официальный канал предложений. Отсутствуют реальные вложения: `images_count = 0`, никаких фиктивных «загружено» нет. Интерфейс не предоставляет несуществующий SLA, не сообщает о принятии жалобы официальной администрацией, не обещает результат в миллисекундах при сетевой задержке.

## Локальный запуск

```bash
python -m pip install -r requirements-lock.txt
export GRAND_RULES_PATH=/absolute/path/to/official/rules.json
python -m uvicorn app.api:app --host 127.0.0.1 --port 8000
```

Откройте `http://127.0.0.1:8000/` (игрок) и `http://127.0.0.1:8000/admin` (оператор). Без `GRAND_RULES_PATH` формы показывают явную ошибку отсутствия правил. Тесты: `python -m pytest -q`.

## Что сделать перед настоящим релизом

Подключить **согласованный официальный backend** Grand Mobile для заявок, авторизацию и проверку прав на сервере, шифрование и retention, реальные вложения и антиспам, а также межбраузерную очередь с audit trail. Перенести локальную историю из browser storage в защищённое хранилище только после privacy review. Проверить все языковые UX-тексты с носителями ru/kk/uz. Загрузить и версионировать официальный набор правил вне Git. Провести доступность, реальные пользовательские тесты и точные замеры p95 в целевой среде.
