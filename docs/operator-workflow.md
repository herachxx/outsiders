# Grand Mobile / Outsiders — рабочая поддержка

## Что действительно реализовано

- Анонимное создание обращения в SQLite `POST /support/tickets`. Сервер выдаёт идентификатор и **секрет доступа к статусу конкретного обращения**. Это не официальный тикет Grand Mobile.
- Безопасный запасной маршрут при отсутствии правил: обращение принимается с `unclassified`, `confidence=0`, `needs_human=true`. Не придумывает точные санкции.
- Первичная категория, приоритет, факты и черновик при загруженных правилах — старый `TriageService`; конкурcный контракт `/triage` и JSONL не изменён.
- Проверка входа оператора по настроенному секрету, подписанная HttpOnly/SameSite cookie, CSRF-токены для мутаций, ограничение числа попыток входа, 8-часовая сессия.
- Очередь (поиск, фильтры, страницы), открытие карточки, редактирование, версионирование, отклонение конфликтов изменения, статусы и аудит событий на сервере.
- `verify`: черновик проверяется через исходный safety gate на стороне сервера. Невозможно перевести обращение в `resolved` без подтверждения проверки.
- До четырёх изображений на обращение, до 5 МБ каждый; допустимы JPEG, PNG, WebP. Файлы проверяются декодером Pillow и переписываются без EXIF. Загрузка только с токеном обращения, скачивание только после входа оператора. **Изображения не интерпретируются моделью как доказательства.**
- Скрипт удаления данных по сроку хранения `python -m scripts.purge_support --days 14` (запуск планируется администратором сервера).
- Административные вызовы не доступны без сессии; при отсутствии секретов вход закрыт.

## Подготовка

Python 3.12+. Команды из корня проекта:

```bash
python -m venv .venv
source .venv/bin/activate    # Windows: .venv\\Scripts\\activate
pip install -e '.[dev]'
```

Задайте переменные окружения (**не коммитьте их в git**):

```bash
export GRAND_ADMIN_PASSWORD='change-this-to-a-long-private-password'
export GRAND_SESSION_SECRET='generate-a-random-secret-32-bytes-or-longer'
export GRAND_DB_PATH='./data/support.sqlite3'
export GRAND_UPLOAD_DIR='./data/uploads'
export GRAND_RULES_PATH='/absolute/path/to/verified/rules.json'
```

Для настоящего деплоя используйте `https`, настройте `GRAND_SECURE_COOKIES=1`, обратный прокси с TLS, backup и контроль доступа к файлам (`data/`). Для тестирования без правил `GRAND_RULES_PATH` можно не задавать; классификация тогда будет ручной, а `verify` недоступен.

```bash
uvicorn app.api:app --host 127.0.0.1 --port 8000
```

- Игрок: `http://127.0.0.1:8000/`.
- Оператор: `http://127.0.0.1:8000/admin` (перенаправит на логин).
- API и схема: `/docs`.

## Жизненный цикл

```text
Игрок отправляет сообщение -> SQLite/new -> правила или ручная маршрутизация
             |                                 |
       добавляет картинки                 Оператор входит
             |                                 |
             +-----------------------> открывает карточку
                                               |
                                        in_review / escalated
                                               |
                                        правит черновик
                                               |
                                        safety verification
                                               |
                                        resolved -> closed
```

На странице игрока идентификатор и секрет сохраняются только в `sessionStorage` текущей вкладки для просмотра статуса. При её закрытии локальная история может исчезнуть; открытая страница не предоставляет публичный список чужих обращений.

Возможные состояния: `new`, `in_review`, `needs_info`, `escalated`, `resolved`, `closed`. Действия логируются. Сохранение статуса и черновика защищено счётчиком версии.

## Границы

1. В репозитории нет официальных API-ключей и соединения с реальным бекендом Grand Mobile. Нажатие «Копировать» **не отправляет** ответ игроку в игре.
2. Сейчас один профиль оператора; нет многопользовательской системы RBAC, SSO и распределения назначений. Подключать к внешнему миру только после отдельного security review.
3. Нет автоматической проверки реальных платёжных данных, аккаунтов, санкций или скриншотов. Никаких обещаний возврата денег или разблокировки.
4. У модели нет права закрывать жалобы автоматически: решение принимает человек.
5. SQLite подходит для одиночной инстанции и пилота, для распределённой production-системы понадобятся PostgreSQL, object storage, job queue, централизованная авторизация и observability.
6. Сроки удаления данных конкурса отличаются по договорённостям: проверьте лицензию и сроки, запускайте purge регулярно и обеспечьте удаление резервных копий.
