# Разметка и политика A3

Статус: draft-2026-10-30. Подтверждение руководителем поддержки ещё не получено. Исходный taxonomy.json загружается отдельно и не публикуется. Код передаёт `policy_draft` в reasons; его нельзя считать утверждённым регламентом.

Разметчик читает только входные сообщения игрока и доступные метаданные. Исторический ответ администратора, verdict, punishment и violation скрыты. Слова обвиняемого фиксируются как отдельное утверждение. Категория описывает содержание, а не доказанность нарушения.

| Код | Граница категории |
|---|---|
| complaint.insult | Обращение о токсичном общении |
| complaint.cheat | Подозрение в нечестном программном преимуществе |
| complaint.dm | Жалоба на боевое взаимодействие и нарушение ролевого сценария |
| complaint.scam | Спор о передаче ценностей или обмане |
| complaint.rmt_ads | Продвижение сторонних ресурсов или реальные денежные сделки |
| complaint.admin | Претензия к действиям администрации |
| complaint.other | Содержательная жалоба за пределами предыдущих классов |
| complaint.invalid | Недостаточно содержания для определения предмета жалобы |
| report.question | Информационный вопрос |
| report.help | Запрос вмешательства из-за игровой проблемы |
| report.complaint | Претензия к другому игроку в репорте |
| report.account | Проблема учётной записи или доступа к имуществу |
| report.payment | Вопрос о денежной операции или её результате |
| report.offtopic | Сообщение без определённой задачи поддержки |

При нескольких темах выбрать основную причину обращения, остальные сохранить в приватной заметке. Спорный случай отметить `needs_adjudication`, не превращать его автоматически в other. Разметка должна содержать category, priority, language, needs_human, annotator_id, policy_version, adjudication_status; эти записи хранятся вне Git.

Порядок приоритетов: p0 — критическая проверка доступа/оплаты/внешней угрозы; p1 — срочный разбор потенциально серьёзного нарушения; p2 — обычный содержательный разбор; p3 — информационный или малосодержательный запрос. Безопасность маршрута важнее эвристической категории. Платежи, аккаунт и жалоба на администратора всегда требуют человека; апелляции тоже передаются человеку независимо от категории.

Временные решения до подтверждения: наличие вложений у жалобы повышает очередь проверки до p1, но не доказывает нарушение; scam консервативно получает p1 без оценки стоимости имущества; отсутствие вложений само по себе не переводит содержательную жалобу в invalid. Для report.help/телепорта сохраняется человек, обещания телепорта нет. Эти решения требуют согласования и проверки на gold-разметке.

Ограничение текущего кода: сигналы критичности распознаются русскими эвристиками; отрицания и смешанные языки могут давать ошибки. Это не измеренная полнота распознавания p0. Исправления словарей и моделей проверяются отдельными языковыми тестами в следующих этапах.

## B1: подготовка и объединение разметки

Из корня проекта:

```powershell
.\.venv\Scripts\python.exe -m scripts.sample_for_labeling --input <train.jsonl.gz> --output <внешняя-папка> --size 800 --seed 42
.\.venv\Scripts\python.exe -m scripts.merge_labels --manifest <manifest.json> --labels <labels-one.csv> <labels-two.csv> --output <новая-внешняя-папка>
```

Пакет содержит `tasks.jsonl` для чтения исходных обращений, `labels.csv` для заполнения и приватный `manifest.json` для связи с исходником и разделения выборок. Выход внутри репозитория и перезапись существующей папки запрещены. Строка задачи содержит только сообщения до первого admin и разрешённые метаданные. Категория и приоритет не подставляются автоматически.

Откройте tasks.jsonl в редакторе, найдите задачу по annotation_id и заполните соответствующую строку CSV. Поля: annotator_id — условный код разметчика; category — код из таблицы; priority — p0–p3; language — ru/kk/uz/en/es/pt/lat/und; needs_human — true/false; adjudication_status — labeled или needs_adjudication. policy_version не менять. Полностью пустые строки шаблона пропускаются, частично заполненные отклоняются. Для спорного случая достаточно кода разметчика и needs_adjudication; такие записи не попадают в gold.

Для пошаговой разметки в терминале можно использовать локальный инструмент:

```powershell
.\.venv\Scripts\python.exe -m scripts.label_cli --package ..\private\annotation-b1 --annotator reviewer_1
```

Он показывает только ещё не размеченные обращения, по одному за раз, и записывает каждое подтверждённое решение в `labels.csv` внутри приватной папки. Enter пропускает обращение на текущем проходе, `q` завершает сеанс; следующий запуск продолжает с оставшихся. Для спорного обращения выберите `needs_adjudication`. Категории ограничены типом обращения, а метка платежа/аккаунта/жалобы на администратора без `needs_human=true` отклоняется. При ошибке ввода запись не сохраняется. Проверяйте выбор перед последним пунктом: инструмент не предлагает редактирование уже сохранённой метки; исправление возможно вручную в CSV. Никакие тексты не отправляются в сеть. Второму разметчику выдайте отдельную копию пустого пакета, чтобы сохранить независимость оценок.

Для независимой второй оценки дать другому разметчику копию пустого шаблона на согласованное подмножество (рекомендуется 20%, включая kk/uz и критические темы). Не показывать ему первую разметку. Объединение создаёт приватные gold.jsonl и conflicts.jsonl: одинаковые оценки получают review_status=agreed, одиночные — single; разногласия не разрешаются голосованием автоматически. После обсуждения подготовить отдельный согласованный файл, сохранив первоначальные оценки. Само название gold не означает, что одиночная метка проверена вторым человеком.

Для такого подмножества используйте `python -m scripts.second_review --package ..\private\annotation-b1 --output ..\private\annotation-b1-second-review --fraction 0.2`. Отбор воспроизводим по annotation_id, включает доступные kk/uz, train/holdout, оба типа и хотя бы один сигнал риска; это не случайная репрезентативная оценка долей. Выход содержит только выбранные задачи, manifest и пустые метки. Второй человек запускает `python -m scripts.label_cli --package ..\private\annotation-b1-second-review --annotator reviewer_2`. Не передавайте ему CSV первого разметчика. После независимой работы объедините оба CSV с **полным** исходным manifest:

```powershell
.\.venv\Scripts\python.exe -m scripts.merge_labels --manifest ..\private\annotation-b1\manifest.json --labels ..\private\annotation-b1\labels.csv ..\private\annotation-b1-second-review\labels.csv --output ..\private\annotation-b1-merged
```

На 31.10.2026 подготовлен `..\private\annotation-b1-second-review`: 160 задач (127 train, 33 holdout), включая 24 kk и 18 uz по исходной подсказке языка. Обе таблицы меток пока пусты; gold отсутствует.

Объединение также сохраняет `agreement.json`: для каждой пары разметчиков — число общих полностью размеченных задач, доля совпадений и невзвешенная Cohen kappa по category, priority, language и needs_human. Одиночные метки и `needs_adjudication` исключены из этих расчётов. При постоянной одинаковой метке kappa не определена (`null`), хотя доля совпадений может быть 100%. Пустой список пар означает отсутствие данных для оценки, а не идеальное согласие. Согласие не доказывает правильность меток; на малом и специально отобранном подмножестве его нельзя переносить на весь поток. Отчёт приватный, содержит коды разметчиков и агрегаты без текстов обращений.

Разделение фиксируется хешем reporter_hash с seed до отбора: 25% групп резервируются для holdout. Не менять seed ради лучших результатов. При последующем обучении на полном исходном наборе также исключать все зарезервированные группы по этому правилу, а не только 200 выбранных тикетов. Контрольные метки нельзя использовать для подбора порогов и шаблонов. Отбор балансирует kind/эвристический язык/сигнал риска/длину/месяц, поэтому доли в выборке не оценивают распространённость категорий в реальном потоке.
