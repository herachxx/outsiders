# E2: задержка и стоимость

## Воспроизведение

```powershell
python -m scripts.benchmark --input <tickets_valid.jsonl> --rules <rules.json> --output <новый-внешний-report.json> --limit 1000
```

Для обученной модели добавьте `--model <model.joblib>`. Поддерживается gzip. Выход вне репозитория, существующий файл не перезаписывается. Отчёт содержит хеши входа, правил, кода и optional модели, среду и агрегаты без обращений. Все ошибки включаются в распределение задержек, а их количество и типы отражаются отдельно. JSON parse, валидация запроса, классификация, retrieval, генерация, safety, валидация ответа и JSON serialization включены в измерение.

Граница измерения — локальная функция pipeline. HTTP, сеть, ожидание в очереди executor и чтение исходного файла исключены. Потоки выполняют запросы с ограничением 1/5/20 одновременно; это не модель поступления запросов в production. Холодный замер включает создание нового сервиса и первый запрос в текущем процессе, но не импорт Python и сброс дисковых кешей. Время бизнес-стадий пока измеряется суммарно, без раздельного profiler. Нужен отдельный HTTP load test перед заявлением end-to-end p95.

## Локальный прогон 30.10.2026

Вход: 1000 строк valid. Backend: эвристики + шаблоны; без обученного classifier, fastText и LLM. История выключена. AMD Ryzen 5 5500U, 12 логических CPU, около 7,4 GiB RAM, Windows 10, Python 3.14.6. Приватный отчёт: `../private/benchmark-e2-v1.json`.

| Потоки | p95, мс | Максимум, мс | Обращений/с | Ошибки |
|---|---:|---:|---:|---:|
| 1 | 0,392 | 1,578 | 5370 | 0/1000 |
| 5 | 0,368 | 107,531 | 5469 | 0/1000 |
| 20 | 0,537 | 89,437 | 3731 | 0/1000 |

Инициализация сервиса: 3,47 мс; первый запрос: 10,73 мс. Высокая параллельность не ускоряет этот CPU pipeline линейно. Один короткий прогон чувствителен к планировщику и фоновой нагрузке; это диагностический результат, не оценка стабильной ёмкости системы.

Все 1000 ответов каждого прогона имеют needs_human=true: текущий эвристический language detector считает язык неуверенным. Safety fallback: 0. Отсутствие fallback не доказывает качество текстов. Низкая задержка текущего baseline не переносится автоматически на будущую модель и не закрывает остальные конкурсные критерии.

## Стоимость

В этом backend нет внешних inference-вызовов: внешняя стоимость на обращение $0. Электроэнергия, оборудование и время администратора не учтены. Это не измерение стоимости LLM. Для будущего API потребуется учёт всех попыток: сумма input_tokens × тарифа входа + output_tokens × тарифа выхода, включая повторные запросы; фиксируются провайдер, модель, тариф и дата. Сейчас токены и тарифы не выдумываются, облачный режим отсутствует.

## Полный процесс и память

```powershell
python -m scripts.benchmark_process --input <tickets_valid.jsonl> --rules <rules.json> --output ../private/process-report.json --predictions ../private/process-predictions.jsonl --limit 1000
```

Опциональная обученная модель передаётся через `--model`. Команда запускает отдельный Python-процесс и измеряет время от его запуска до завершения: импорты, загрузку правил/модели, чтение входа, обработку и запись предсказаний. История выключена, формат submission. Выходы должны быть новыми и находиться вне репозитория. В отчёте — количество строк, ошибки, хеши входных строк, правил и кода, среда, время и пик резидентной памяти дочернего процесса по данным ОС. Родительский процесс, другие процессы, GPU/VRAM и HTTP не включены. Это суммарное время, не p95 отдельных обращений.

Прогон 31.10.2026 на 1000 строк valid: **1,918 с; 33 247 232 байта RAM = 33,25 МБ (31,71 МиБ); ошибок 0**. Backend: эвристики и шаблоны без обученной модели. Приватные файлы: `../private/benchmark-process-v1.json` и `../private/benchmark-process-v1-predictions.jsonl`. Это один прогон на текущем Windows-компьютере с обычными файловыми кешами; качество не оценивалось. Сравнение с чужими «секунды / МБ» возможно только при одинаковых данных, оборудовании, модели и границе замера.

Проверены подсчёт ошибок, включение неуспешных запросов в p95, агрегация без исходного текста и реальный локальный прогон 1000 строк. E2 подтверждает локальную задержку существующего baseline; отдельные профили стадий и измерения итоговой обученной конфигурации ещё нужны.

## HTTP-прогон 31.10.2026

Отдельный скрипт проверяет полный локальный HTTP-запрос и ответ. Сервер нужно запустить отдельно с теми же правилами; URL ограничен localhost/127.0.0.1. Пример:

```powershell
python -m scripts.benchmark_http --url http://127.0.0.1:8000 --output ../private/benchmark-http-e2-v1.json --requests 1000
```

Используется один синтетический вопрос об аккаунте, повторённый 1000 раз на каждый уровень параллелизма. Сырые обращения не нужны. Время включает HTTP, обработку FastAPI и ожидание в очереди сервера, но исключает ожидание задания в клиентском пуле. Нагрузка замкнутая, из одного клиента на том же компьютере; это диагностический прогон, а не оценка production ёмкости.

На текущем эвристическом сервере без модели, при 1/5/20 клиентских потоках p95 составил 27,4/34,3/79,0 мс, пропускная способность 84/232/269 запросов/с. Ошибок: 0 из 1000 на каждом уровне. Все три p95 ниже лимита 5 с. Отчёт: `../private/benchmark-http-e2-v1.json`. Измерение не доказывает качество классификации, текста, цитат или работу будущей модели. Для конкурсного заявления нужен прогон финальной конфигурации и репрезентативной смеси обращений.
