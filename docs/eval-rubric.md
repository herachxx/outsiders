# D4: слепая оценка черновиков

Технический пакет готов; оценки должны поставить администраторы и носители языка. Реальные результаты не подменяются автоматическими баллами.

## Подготовленный пакет

`C:\Users\kulda\Documents\Decentrathon\private\draft-review-d4-v1` содержит 100 пар из train. Группы holdout из B1 и хеш-разделения по его seed исключены. Кандидат — текущий эвристический сервис с шаблонами, без обученного классификатора. Для каждого обращения показывается одинаковый контекст до первого admin, затем A и B в случайном порядке. Исторический ответ — первое сообщение admin; это может быть неполный ответ, что следует учитывать.

- Оценщикам передать только `tasks.jsonl` и копию `ratings.csv`.
- `private-key.jsonl` хранит источник сторон, исходный ticket_id и полный прогноз кандидата. Не передавать оценщикам.
- `candidate.json` фиксирует хеши исходников, шаблонов, правил, размер и seed. Тексты ответов уже заморожены в заданиях.
- Все файлы приватные и остаются вне Git. Не передавать реальные обращения внешним сервисам без отдельного разрешения.

Отсутствие названия источника не гарантирует полной слепоты: характер шаблонов может подсказать происхождение. Автоматической рассылки оценщикам нет. Простая случайная выборка не гарантирует достаточно kk/uz: после подтверждения языков нужны отдельные дополнительные наборы с явным описанием способа отбора. Сам language_hint в закрытом ключе не является ручной разметкой.

## Работа оценщика

Для каждой пары заполнить обе строки A/B с одним reviewer (псевдоним), language (подтверждённый язык обращения), native=true/false, score от 1 до 5, hallucination=true/false и необязательным comment. Каждый оценщик получает отдельную копию формы; перед подсчётом формы объединяются с сохранением строк. Желательно минимум два независимых оценщика на пару. Для kk/uz принимаются только оценки носителей. Споры о языке и галлюцинациях сначала разрешаются экспертом; флаги в отчёте не считаются автоматически доказанными ошибками.

Шкала:

1. Непригодно: опасный совет, неверный смысл или ответ не помогает.
2. Нужна существенная переработка: пропущена основная проблема или непонятен следующий шаг.
3. Пригодно после правки: смысл сохранён, но есть заметные недостатки.
4. Хорошо: полезный, точный и вежливый ответ с небольшой правкой.
5. Готово к использованию: решает запрос в пределах доступных сведений, не добавляет неподтверждённых фактов.

Оценивать конкретность, полезность, грамматику, тон, соответствие языку и следующий шаг. Отдельно отмечать выдуманные правила, санкции, действия, факты и якобы просмотренные материалы. Наличие вложений не доказывает нарушение. Если для проверки цитаты нужны правила, координатор предоставляет одинаковую актуальную базу обоим оценщикам. Не считать исторический ответ безусловно правильным.

Комментарии должны объяснять нужную правку; не включать пароли и платёжные реквизиты. Публичный список улучшений составляется после экспертного разбора без исходных текстов и идентификаторов.

## Команды

```powershell
python -m scripts.evaluate_drafts prepare --input <train.jsonl.gz> --rules <rules.json> --exclude-manifest <B1/manifest.json> --output <новый-внешний-каталог> --size 100 --seed 42
python -m scripts.evaluate_drafts summarize --key <private-key.jsonl> --ratings <заполненный-ratings.csv> --output <новый-внешний-report.json>
```

Выход не перезаписывается. Подсчёт отвергает неизвестные/повторные оценки, незавершённые пары, неверные баллы и отсутствие подтверждения носителя для kk/uz. Пустая форма даёт ноль оценённых пар. Идентичность и компетентность оценщиков организатор проверяет отдельно: поле native — декларация, не удостоверение.

Отчёт содержит среднее и медиану баллов, среднюю парную разницу candidate−historical, 95% bootstrap-интервал по обращениям (2000 повторов), долю обращений с флагом галлюцинации, среднее с обнулением таких обращений и среднее абсолютное расхождение оценщиков. Повторные оценки сначала усредняются внутри обращения. Интервал при малой или однообразной выборке может быть вырожденным и не доказывает превосходство; для конкурсного обнуления галлюцинации должны пройти adjudication. Срезы по языкам публикуются с числом пар. Это не формальный ICC/kappa. Сырые комментарии и тексты в агрегатный отчёт не включаются.
