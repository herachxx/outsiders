# B2: подготовка обучения классификатора

Инструменты готовы. Реальная модель и её качество пока не получены: пакет B1 требует ручных меток. Синтетические тесты проверяют работу кода, а не конкурсную accuracy.

## Входы и границы данных

Используются `tasks.jsonl` и `manifest.json` из B1, а также `gold.jsonl` от `scripts.merge_labels`. Заполнить `labels.csv` и объединить метки нужно по [руководству разметчика](annotation-guide.md). Строки конфликтов в обучение не входят. Метки одного разметчика допускаются, но не считаются экспертным согласием; состав review_status отражён в отчёте.

Тренировщик проверяет совпадение задач с полным manifest, уникальность ID, категорию и kind, версию политики, происхождение меток и отсутствие общих заявителей между train и holdout. Список зарезервированных заявителей проверяется даже для неразмеченных задач. Нельзя подавать урезанный manifest или добавлять другие обращения зарезервированного заявителя как train. Проверка относится к предоставленному manifest, а не к неизвестным внешним файлам.

Признаки — только нормализованный текст сообщений player до первого admin. Ответы admin, последующие сообщения player, reported_player, verdict, punishment, violation, язык разметчика и целевые метки не входят в признаки. Один preprocessing используется при обучении и работе сервиса. `images_count` остаётся исходным счётчиком вложений обращения; сообщения с вложениями после admin игнорируются.

## Запуск (PowerShell, из корня репозитория)

```powershell
.\.venv\Scripts\python.exe -m pip install -e '.[dev,ml]'
.\.venv\Scripts\python.exe -m scripts.train `
  --tasks ..\private\annotation-b1\tasks.jsonl `
  --manifest ..\private\annotation-b1\manifest.json `
  --gold ..\private\annotation-b1-labeled\gold.jsonl `
  --output ..\private\classifier-b2-v1 `
  --seed 42
```

Путь `annotation-b1-labeled` — пример будущего результата merge, а не уже готовая разметка. Выходной каталог должен быть новым и находиться вне репозитория. Пустой gold завершает команду кодом 2 без создания модели. Некорректные метки, несовпадение manifest и существующий выходной каталог также приводят к отказу.

Обучаются отдельные модели для complaint/report: word TF-IDF 1–2, char TF-IDF 2–5, LogisticRegression с балансировкой классов, C=2 и max_iter=1000. Лимиты словаря — 40 000 словесных и 80 000 символьных признаков на тип обращения. Тип с менее чем двумя размеченными классами пропускается; если обучать нечего, команда завершается ошибкой. Отсутствующие классы перечислены в отчёте, модель не может предсказывать их без защитного правила или fallback.

## Проверка и артефакты

Внутри размеченного train выполняется до пяти GroupKFold-разбиений по заявителю с заданным seed. TF-IDF обучается заново только на обучающей части каждого fold. На тех же проверочных строках сравниваются сырая модель, текущие regex и предсказание наиболее частого класса обучающей части. Отчёт включает accuracy и macro-F1 по всем категориям данного kind, включая отсутствующие (zero_division=0). Это метрики категории, не macro-F1 приоритета из критериев конкурса.

При недостатке групп проверка пропускается; fold с единственным обучающим классом также пропускается. Статусы complete/partial/skipped и число реально оценённых строк обязательны. Даже complete означает только технически завершённую CV, а не достаточную статистическую надёжность. Выборка B1 стратифицирована и не отражает естественные частоты обращений.

После CV итоговые модели обучаются на всём размеченном train. Holdout не используется ни для словаря, ни для настройки, ни для отчётных метрик. Сравнение качества полного сервиса с защитными правилами и калибровка — последующие этапы.

Внешний каталог содержит:

- `model.joblib` — модели, версия preprocessing/политики, seed, версии библиотек и метаданные;
- `report.json` — агрегаты классов и разметки, CV и отпечаток обучающих данных без исходных текстов и ID.

Словарь модели может содержать фрагменты обращений, поэтому сам артефакт тоже является приватным. Загружать можно только собственные доверенные файлы: joblib способен выполнять код при десериализации. Проверка версии не делает неизвестный файл безопасным. Для воспроизведения используйте версии окружения из отчёта; загрузчик требует ту же версию scikit-learn, политики и preprocessing. Подробности: [сохранение моделей scikit-learn](https://scikit-learn.org/stable/model_persistence.html), [защита от утечки через Pipeline](https://scikit-learn.org/stable/common_pitfalls.html).

## Подключение

```powershell
$env:GRAND_RULES_PATH = 'C:\path\outside\repo\rules.json'
$env:GRAND_MODEL_PATH = 'C:\Users\kulda\Documents\Decentrathon\private\classifier-b2-v1\model.joblib'
.\.venv\Scripts\python.exe -m uvicorn app.api:app --host 127.0.0.1 --port 8000
.\.venv\Scripts\python.exe -m app.batch --input C:\path\input.jsonl --output C:\path\output.jsonl --rules C:\path\rules.json --model $env:GRAND_MODEL_PATH
```

Без настройки модели работает прежняя эвристика. Если модель не обучена для kind, текст пуст или все признаки неизвестны, используется эвристика с причиной `classifier_fallback`. Настроенный, но отсутствующий/несовместимый файл останавливает запуск, без скрытой подмены режима. Для предсказания моделью добавляется `classifier_uncalibrated`; confidence остаётся 0.0 до B3.

Распознанная эвристикой проблема платежа, аккаунта или жалоба на администратора сохраняет чувствительную категорию даже при ином прогнозе модели (`sensitive_category_override`). Это защита от регрессии известных сценариев, не гарантия распознавания всех формулировок и языков.

Проверки: `python -m pytest -q` с установленным extra `ml`. Без него ML-тесты явно пропускаются; это не полная проверка B2.
