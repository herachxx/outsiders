# Контракт A2, версия 0.2

`POST /triage` принимает `kind: complaint|report` и `messages` (1–100), в том числе хотя бы одно сообщение `player`. Роль: `player|reported_player|admin`, текст — строка до 20 000 символов, `ts` — необязательная строка, `attachments` — неотрицательное целое число вложений. Дополнительные поля запроса перечислены в `TriageRequest` и OpenAPI `/docs`. Неизвестные поля запрещены; строки вместо чисел и отрицательное число вложений отклоняются. Для поля верхнего уровня `images_count` действует то же правило. Метаданные вложений не подтверждают нарушение.

HTTP принимает только контракт обращения. Batch дополнительно принимает историческую запись handout: перед валидацией удаляются `ticket_id`, `created_at`, `lang`, `status`, `verdict`, `punishment`, `violation`, `category`, `priority`. Эти поля не попадают в признаки. Остальные неизвестные поля не игнорируются. Исторические `admin` остаются совместимыми с форматом, но сервис их не использует при предсказании.

Выход проверяется Pydantic: категория — один из 14 кодов, приоритет p0–p3, язык ru/kk/uz/en/es/pt/lat/und, confidence — конечное число от 0 до 1. Булевы поля строго типизированы. Сейчас confidence=0 отражает отсутствие калиброванной модели, а не оценку качества черновика.

По умолчанию HTTP и batch возвращают `draft_reply.cited` как массив строк номеров пунктов согласно примеру PDF. Для аудита `POST /triage?format=internal` и CLI `--format internal` сохраняют объекты `{section_id, ref, rules_hash, excerpt}`. Адаптер меняет только сериализацию: безопасность проверяется по полному внутреннему ключу. Существование и релевантность пунктов нельзя проверять только по внешнему ref. Окончательная совместимость с hidden test требует подтверждения организатором; текущий формат воспроизводит доступный пример.

Ошибки: HTTP 422 — неверный запрос, 503 — нет правил или выход сервиса не соответствует схеме. Batch сохраняет порядок и число строк; некорректная строка даёт `{"error":"invalid_input"}`, нарушение схемы ответа — `{"error":"invalid_output"}`. Ошибки не содержат текст или идентификаторы обращения. Повреждённый gzip/ошибка файловой системы останавливают команду с ненулевым кодом.

Пример запуска: `python -m app.batch --input <tickets.jsonl.gz> --output <pred.jsonl> --rules <rules.json>`. Все файлы данных и результатов должны находиться вне Git.

## Опциональная модель B2

API загружает доверенный локальный артефакт из `GRAND_MODEL_PATH`, batch — из `--model`. Без них остаётся эвристический режим. Схемы запроса/ответа не меняются; confidence остаётся 0.0. Причины `classifier_uncalibrated`, `classifier_fallback`, `sensitive_category_override` описаны в [инструкции обучения](training.md). Несовместимая настроенная модель останавливает запуск. Сообщения после первого admin не влияют на текстовые признаки и признаки вложений сообщений.
