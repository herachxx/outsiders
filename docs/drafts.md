# D2: черновики по типу обращения

`app/draft.py` собирает черновик из `app/templates/drafts.json`. Шаблоны ru/kk/uz/en покрывают платёж, доступ к аккаунту, техническую помощь, вопрос, жалобу на игрока и администратора. Прочие языки используют английский fallback; draft_reply.lang указывает фактический язык шаблона, поле lang сохраняет определённый язык обращения.

Поле region в наборе содержит географические коды cis/uz/kz; они не определяют конкретный игровой сервер. Если поле отсутствует, пусто или содержит один из этих кодов (без учёта регистра и внешних пробелов), черновик запрашивает сервер. Для совместимости текущий интерфейс также передаёт явно введённый сервер через region; прочие непустые значения пока считаются указанным сервером. Это ограничение контракта, а не проверка существования сервера. Для жалобы без reported_nick/reported_hash запрашивается участник. Наличие вложений сопровождается оговоркой об отсутствии проверки содержимого. Отрицания и утверждения игрока не превращаются в факты, исходный текст не вставляется в шаблон. Цитаты поступают только после проверки RuleIndex и сопровождаются оговоркой о проверке применимости.

Нет интеграции отправки: текст не утверждает, что обращение фактически передано, деньги возвращены или нарушение установлено. Пароли и коды не запрашиваются. Квитанция запрашивается с сокрытием реквизитов. Для игрового вопроса без опоры запрашивается уточнение. Умение отвечать на конкретные игровые вопросы потребует проверенной базы знаний; этот шаг её не создаёт.

Шаблоны — предварительные тексты, не утверждённые администраторами и носителями kk/uz. Слепая оценка качества и сравнение с реальными ответами ещё не выполнены. LLM backend не подключён: оснований и измерений для его выбора пока нет. Следующий этап D3 — проверки безопасности готового ответа.

Стиль ответов сверен с историческими ответами администраторов на valid: у жалоб это приветствие, благодарность и подпись, у репортов очень короткие ответы (медиана около 28 символов). Поэтому у жалоб черновик начинается с приветствия и заканчивается подписью «администрация Grand Mobile», у репортов только короткое приветствие. Если вложений нет, просим видеозапись (фрапс): в исторических отказах причиной чаще всего называют недостаток видео. Приветствия, подпись и фразу о фрапсе на kk/uz написал не носитель; их нужно проверить.

Язык черновика: если язык обращения не определён (und, lat), используется язык сервера из поля `server_lang`, а при его отсутствии русский (основная аудитория набора). Тот же выбор применяется в резервном ответе проверки безопасности.

Для типовых жалоб (оскорбление, читы, DM, обман, реклама за деньги, невалидная) есть отдельные уточняющие вопросы: где и когда произошло, какое преимущество используется, как начался конфликт, что передавалось и о чём договорились. После них идёт общая фраза о проверке администратором; другое и жалобы через репорт используют общий текст. Формулировки на kk/uz написаны не носителем.

Если у обращения есть вложения, черновик говорит, что материалы рассмотрит администратор (раньше: «ещё не проверено»). Это описание процесса, а не вывод о нарушении. Казахские тексты для проверки носителем собраны в [kk-review.md](kk-review.md).

Если для жалобы найден пункт правил, в черновик добавляется осторожная фраза «Возможное нарушение: пункт X правил: «…». Меру ответственности определяет администратор после проверки». Цитата берётся из самого правила (первое предложение до списка санкций, санкции не цитируются), поэтому ничего не выдумывается и наказание не обещается. В казахских и узбекских черновиках указывается только номер пункта: текст правил русский, и смешивать его с казахским текстом нельзя.
