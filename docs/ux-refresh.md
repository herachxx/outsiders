# Обновление рабочего интерфейса 31.10.2026

## Как пользоваться

1. Запустите проект прежним START_WINDOWS.bat или START_LINUX.sh. При первом запуске создайте пароль оператора. Переключатель позволяет увидеть введённый пароль перед сохранением.
2. На странице игрока ссылка «Панель оператора» находится сверху. В панели есть обратная ссылка «Страница игрока». Повторно создавать пароль не нужно; при завершившейся сессии откроется вход.
3. Блок статуса показывает связь с сервером, доступность правил и наличие классификатора. «Классификация по правилам» означает работающий детерминированный режим, а не подключённую ML-модель. При отсутствии правил обращения принимаются для ручной обработки.
4. В панели выберите обращение слева. Превью показывает сообщение, статус и понятный уровень срочности. Доступны поиск, фильтр срочности/проверки и отдельный фильтр статуса.
5. На широком экране исходное сообщение и черновик находятся рядом. Материалы и история открываются отдельными вкладками. На телефоне переход к обращению и обратно выполняется кнопкой «К списку».
6. Для знакомства с процессом нажмите «Новое обращение», затем «Заполнить тестовым примером». Тест создаётся только после явного нажатия «Создать обращение».
7. «Сохранить правку» сохраняет текст без завершения обращения. Проверка по-прежнему принимает утверждённый шаблон; свободная правка сохраняется для ручного разбора. Отказ объясняется словами, а не техническим кодом.
8. «Отправить вручную» проверяет ответ, копирует текст и запрашивает подтверждение фактической отправки оператором. Только после подтверждения тикет отмечается решённым. Интеграции отправки в игру нет. В списке статусов недопустимые переходы отключены.

## Визуальные решения

Рабочая палитра: красный акцент #c72f40, тёмный синий #24364b, фон #edf1f5, белые рабочие поверхности, вторичный текст #536478, границы #dce2e8. Системный Segoe UI сохраняет работу без внешних шрифтов. Пространство разделено по задачам: очередь, исходное сообщение, ответ и решение. Цвет дополнен текстовыми обозначениями; предусмотрены клавиатурный фокус и reduced motion.

В качестве ориентира изучена организация [Zendesk Agent Workspace](https://support.zendesk.com/hc/en-us/articles/4408821259930-About-the-Zendesk-Agent-Workspace/): исходный контекст, ответ и состояние обращения доступны в одном рабочем пространстве. Код и оформление реализованы в этом проекте самостоятельно.

## Проверка

Полный набор: 301 тест, одно предупреждение устаревшего API зависимости Starlette. Дополнительно проверен синтаксис JavaScript. Новые тесты проверяют реальное состояние помощника, локальную выдачу ассетов, обратные переходы, уникальность id и соответствие подписей полям.

В изолированном браузерном экземпляре на localhost проверены: вход оператора; пустая очередь; создание синтетического обращения; классификация и черновик; проверка шаблона; сохранение правки; отказ проверки произвольного текста; восстановление исходного шаблона; переход игрок → оператор → игрок без повторного входа; узкий и широкий экраны; завершение тестового тикета через ручную отправку. Реальные обращения и учётные данные для этой проверки не использовались. Первый запуск с созданием пароля проверен автоматическими тестами, а не ручным вводом нового пароля в браузере.

Это проверенные сценарии, а не гарантия отсутствия всех ошибок. Работа с большим количеством операторов и внешними игровыми каналами остаётся за пределами локального прототипа.
