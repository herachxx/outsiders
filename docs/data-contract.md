# A1: инвентаризация данных

Потоковая проверка `python -m scripts.inspect_data <train.jsonl.gz> <valid.jsonl> --rules <rules.json> --taxonomy <taxonomy.json>` выводит только агрегаты. Исходные обращения, идентификаторы и тексты в отчёт не входят. Ненулевой exit code означает ошибку структуры, повторный ID или отсутствие сообщения игрока.

Проверка 30.10.2026: train — 118 337, valid — 1 000 строк; ошибок JSON/проверяемой структуры, повторных ticket_id внутри каждого файла и отсутствующих сообщений игрока не найдено. Правила: 11 разделов, 266 пунктов, 101 уникальный ref; составной ключ `(section_id, ref)` уникален. Taxonomy: 14 категорий, 4 приоритета.

Это инвентаризация, а не полная валидация контракта A2: она не подтверждает корректность вердиктов, дат, разметки языка или истинность утверждений игроков. Категории и приоритеты требуют независимой разметки. Правила с одинаковым ref в разных разделах нельзя объединять.
