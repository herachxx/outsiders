# C3: история и точные повторы

Batch: по умолчанию история включена для входов до 200 МБ (`--no-history` отключает, `--history` включает принудительно); метки времени без часового пояса считаются UTC, повторное использование ticket_id не даёт ошибку, а добавляет причину `history_identity_conflict`. Требуются ticket_id и created_at с часовым поясом, а также reporter_hash. Вход буферизуется в памяти, обрабатывается по времени, результат возвращается в исходном порядке. Равные времена упорядочиваются по исходной строке. Некорректная строка сохраняет свою позицию. Без времени/ID история недоступна, добавляется history_metadata_missing_or_invalid. Без заявителя или текста история также не используется.

HTTP: задайте GRAND_HISTORY_PATH на SQLite-файл вне репозитория (родительская папка должна существовать), передавайте стабильный заголовок X-Ticket-ID. Используется время приёма сервером. Без заголовка история не применяется. Повтор с тем же ID и проблемой не увеличивает счётчик; другой текст/заявитель под тем же ID даёт HTTP 409. Batch выдаёт history_identity_conflict. Идемпотентность сохраняется только пока запись удерживается в истории.

Ключ проблемы: заявитель, kind, region, reported_hash либо reported_nick и нормализованный текст player до admin. Регистр, ё/е и пробелы нормализуются. Второе совпадение даёт duplicate_exact и is_spam_or_duplicate=true. Пятое в окне [текущее время − 3600 секунд, текущее время] даёт five_tickets_within_hour и человека. Точная граница 60 минут включается. Это признак повтора, не доказательство спама и не основание наказания.

SQLite хранит только SHA-256 идентификаторов/ключа проблемы, время и счётчик. Это всё равно приватные производные данные. Старые строки удаляются при поступлении следующего полноценного обращения; фонового удаления в простое нет. Удаление строк не гарантирует стирания освобождённых страниц SQLite с диска. HTTP соединение закрывается при завершении приложения. Запись выполняется транзакционно; разные заявители не объединяются. Batch каждый запуск использует новую историю в памяти, HTTP — постоянный файл.

Ограничения: семантическая близость и перефразировки пока не определяются, similarity-порог и precision/recall не измерены. Пустые/неполные метаданные не позволяют обнаружить все повторы. Дедупликация opt-in и не меняет категории/приоритеты. Для крупного batch потребуется потоковая внешняя сортировка вместо буферизации. C3 реализован частично; качественная оценка требует вручную размеченных пар.
