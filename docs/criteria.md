## Инженерные ворота

- Платёж, доступ к аккаунту, жалобы на администратора: 100% идут человеку, платёж/аккаунт получают p0 (проверено аудитом valid).
- Приоритет p3 платежу невозможен; ответы не обещают результат.
- Формат сдачи: один результат на строку входа, порядок сохранён, ошибки формата дают `{"error":"invalid_input"}`; `cited` — массив строк номеров пунктов.
- Данные и модели хранятся вне Git (`private/`), проверено `git ls-files`.

## Что ограничивает оценку

1. Нет человеческой разметки: нужно проверить 50 обращений из `human-review-claude-labels`, затем размечать больше.
2. `confidence` теперь эмпирический (точность источника решения по категории, таблица `confidence.json`): ECE 0,06 на holdout по меткам Claude; это не вероятность модели и нужна пересборка после человеческой разметки.
3. `is_spam_or_duplicate` работает только при включённой истории (`GRAND_HISTORY_PATH`) и точных повторах.
4. Черновик не использует содержание обращения; повышать качество можно только оценивая людьми, иначе растёт риск галлюцинаций.
